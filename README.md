# Live Classifier

نمونهٔ اپ اندروید برای طبقه‌بندی تصویر دوربین زنده با مدل آمادهٔ **EfficientNet-Lite0**. مدل داخل پروژه قرار دارد؛ پس از نصب APK، پردازش روی خود گوشی و بدون اینترنت انجام می‌شود.

**برای گرفتن APK بدون Android Studio، [راهنمای فارسی قدم‌به‌قدم](QUICKSTART-FA.md) را بخوانید.**

- اندروید ۷ یا جدیدتر، همراه دوربین؛ نصب روی گوشی واقعی برای بررسی سرعت و کیفیت.
- Kotlin و CameraX برای دوربین؛ MediaPipe Image Classifier برای اجرای مدل `.tflite`.
- رابط فارسی، با مدل آمادهٔ حدود ۱۸ مگابایتی و ۱۰۰۰ برچسب انگلیسی ImageNet؛ این نمونه به دادهٔ آموزشی شما نیاز ندارد.
- طبقه‌بندی ناحیهٔ مرکزی تصویر؛ این اپ دور اشیا کادر نمی‌کشد و مکان چند شیء را پیدا نمی‌کند.
- نمایش سه نتیجهٔ برتر، زمان پردازش برحسب میلی‌ثانیه و تعداد نتایج در ثانیه؛ توقف و ادامهٔ تحلیل با یک دکمه.
- استفاده از دوربین پشت؛ اگر گوشی دوربین پشت نداشته باشد، تلاش برای استفاده از دوربین جلو.
- ساخت APK آزمایشی با GitHub Actions؛ بدون کلید سرویس یا حساب فروشگاه.

مدل ممکن است برای اشیای خارج از کلاس‌های آموزشی، نور نامناسب یا پس‌زمینهٔ شلوغ نتیجهٔ اشتباه بدهد. امتیاز نمایش‌داده‌شده تضمین درستی نتیجه نیست. تحلیل تصویر برای کاهش مصرف و گرما حداکثر حدود ۵ بار در ثانیه انجام می‌شود؛ سرعت واقعی به گوشی بستگی دارد. پیش‌نمایش دوربین پیوسته زنده می‌ماند، حتی وقتی تحلیل را متوقف کنید.

## نحوهٔ اجرای پردازش

این پروژه از **MediaPipe Tasks Vision 0.10.35** برای اجرای مدل TFLite استفاده می‌کند و مستقیماً APIهای LiteRT را فراخوانی نمی‌کند. فریم‌های CameraX با `ImageAnalysis` دریافت می‌شوند و روی یک executor تک‌رشته‌ای در پس‌زمینه، با `RunningMode.IMAGE` طبقه‌بندی می‌شوند. بنابراین ورودی اپ دوربین زنده است، ولی هر فریم منتخب به‌صورت مستقل و همگام تحلیل می‌شود. فریم‌های قدیمی در صف انباشته نمی‌شوند.

پیش‌نمایش مربعی و بخش تحلیل از viewport مشترک استفاده می‌کنند تا برش مرکزی تحلیل‌شده با تصویر نمایش‌داده‌شده هماهنگ باشد. گرفتن اجازهٔ دوربین، هدایت به تنظیمات در صورت نیاز و تلاش مجدد پس از خطا در اپ پیش‌بینی شده‌اند. اپ مجوز اینترنت درخواست نمی‌کند.

## وضعیت بررسی

موفقیت ساخت APK با اجرای سبز workflow مشخص می‌شود. آزمایش دوربین و سرعت اجرا باید روی گوشی واقعی انجام شود؛ این سند به‌تنهایی تأیید اجرای اپ روی دستگاه نیست.

## استفاده از مدل خودتان در آینده

فایل مدل فعلی را تنها با یک مدل طبقه‌بندی سازگار با **MediaPipe Image Classifier** جایگزین کنید. یکسان‌بودن پسوند `.tflite` کافی نیست: نوع و شکل ورودی/خروجی، برچسب‌ها، metadata و تنظیمات نرمال‌سازی باید با API سازگار باشند. نام فایل مورد استفاده در کد نیز باید با فایل جدید هماهنگ شود. پیش از جایگزینی در اپ، خروجی مدل تبدیل‌شده را با چند تصویر شناخته‌شده بررسی کنید.

workflow برای اطمینان از سلامت مدل، SHA-256 فایل را بررسی می‌کند. بعد از جایگزینی مدل، hash جدید را نیز در مرحلهٔ **Verify bundled model and Gradle wrapper** فایل `.github/workflows/build-apk.yml` جایگزین کنید. در PowerShell و از ریشهٔ پروژه:

```powershell
Get-FileHash -Algorithm SHA256 .\app\src\main\assets\efficientnet_lite0.tflite
```

فقط hash مربوط به مدل را تغییر دهید؛ hash فایل Gradle wrapper مربوط به ابزار دیگری است.

این پروژه مدل را آموزش نمی‌دهد؛ هدف آن اجرای یک مدل آماده روی دوربین موبایل و فراهم‌کردن مسیر ساخت APK است.
